                    1. THEME SYSTEM ARCHITECTURE
===============================================================================

1.1 OVERVIEW
   The application uses a centralized theme system built with React Context
   and Material-UI (MUI). The system supports:
   
   ✓ Multiple preset themes
   ✓ Custom user-created themes
   ✓ Independent light/dark mode themes
   ✓ Real-time theme switching
   ✓ API-backed theme persistence
   ✓ User profile theme syncing

1.2 CORE COMPONENTS
   
   Component              | Location                    | Purpose
   ────────────────────────────────────────────────────────────────────
   ThemeContext.jsx       | src/context/                | State management & API
   theme.js               | src/theme/                  | Theme definitions
   ThemeSettings.jsx      | src/pages/                  | UI for customization
   Layout.jsx             | src/                        | Theme application

1.3 THEME TYPES
   
   PRESET THEMES (client_id = null)
   • Built-in themes provided by the system
   • Cannot be edited or deleted by users
   • Marked with isDefault flag for defaults
   
   CUSTOM THEMES (client_id != null)
   • Created by users through ThemeSettings
   • Fully editable and deletable
   • Stored per client in database

1.4 MODE SUPPORT
   
   • Light Mode - Optimized for daylight viewing
   • Dark Mode - Reduced eye strain for low-light
   • Each user selects separate theme for each mode
   • Mode toggle persists in localStorage

1.5 DATA FLOW ARCHITECTURE
   
   ┌─────────────────┐
   │  User Profile   │
   │  (Backend API)  │
   └────────┬────────┘
            │ fetch
            ▼
   ┌─────────────────┐
   │  ThemeContext   │ ◄─── User interaction
   │   (React)       │
   └────────┬────────┘
            │ create
            ▼
   ┌─────────────────┐
   │   MUI Theme     │
   │    Object       │
   └────────┬────────┘
            │ provide
            ▼
   ┌─────────────────┐
   │  All Components │
   │  (useTheme())   │
   └─────────────────┘

                3. THEME CONTEXT & STATE MANAGEMENT
===============================================================================

3.1 THEME CONTEXT PROVIDER (ThemeContext.jsx)
   
   Location: src/context/ThemeContext.jsx
   Export: ThemeProvider (component), useThemeMode (hook)
   
   STATE VARIABLES:
   ┌─────────────────────────┬──────────┬─────────────────────────────────┐
   │ Variable                │ Type     │ Purpose                         │
   ├─────────────────────────┼──────────┼─────────────────────────────────┤
   │ presetThemes            │ Array    │ Built-in themes (client_id=null)│
   │ customThemes            │ Array    │ User themes (client_id!=null)   │
   │ themesLoading           │ Boolean  │ Loading state for API fetch     │
   │ selectedLightThemeId    │ Number   │ Active theme ID for light mode  │
   │ selectedDarkThemeId     │ Number   │ Active theme ID for dark mode   │
   │ mode                    │ String   │ Current mode: 'light' or 'dark' │
   └─────────────────────────┴──────────┴─────────────────────────────────┘

3.2 CONTEXT API METHODS
   
   METHOD                          | PARAMETERS               | PURPOSE
   ────────────────────────────────────────────────────────────────────────
   toggleTheme()                   | none                     | Switch light ↔ dark
   syncUserTheme(themeData)        | {light: {id}, dark: {id}}| Sync from profile
   applyPresetTheme(light, dark)   | lightId, darkId          | Apply both themes
   resetToDefault()                | none                     | Reset to defaults
   reloadThemes()                  | none                     | Re-fetch from API
   setSelectedLightThemeId(id)     | themeId                  | Set light theme
   setSelectedDarkThemeId(id)      | themeId                  | Set dark theme

3.3 THEME INITIALIZATION LIFECYCLE
   
   STEP 1: Component Mount
   ────────────────────────────────────────────────────────────────────
   • ThemeProvider component mounts in app root
   • useEffect triggers loadThemes()
   • API call: fetchClientTheme()
   • Response contains all themes (preset + custom)
   
   STEP 2: Theme Separation
   ────────────────────────────────────────────────────────────────────
   • Filter themes by client_id === null → presetThemes
   • Filter themes by client_id !== null → customThemes
   • Set themesLoading = false
   
   STEP 3: User Sync
   ────────────────────────────────────────────────────────────────────
   • Layout.jsx calls syncUserTheme(user.theme)
   • Extract light.id and dark.id from user profile
   • Update selectedLightThemeId and selectedDarkThemeId
   
   STEP 4: Theme Creation
   ────────────────────────────────────────────────────────────────────
   • Determine activeThemeId based on current mode
   • Find theme object in presetThemes + customThemes
   • Extract theme_properties.palette
   • Call createCustomTheme(mode, palette)
   • Return MUI theme object
   
   STEP 5: Application
   ────────────────────────────────────────────────────────────────────
   • MuiThemeProvider receives theme object
   • CssBaseline applies global styles
   • All child components can access via useTheme()

3.4 ACTIVE THEME RESOLUTION CODE
   
   // Get active theme ID based on current mode
   const activeThemeId = useMemo(() => {
     return mode === 'light' ? selectedLightThemeId : selectedDarkThemeId;
   }, [mode, selectedLightThemeId, selectedDarkThemeId]);
   
   // Create theme object
   const theme = useMemo(() => {
     if (activeThemeId) {
       const allThemes = [...presetThemes, ...(customThemes || [])];
       const selectedTheme = allThemes.find(t => t.id === activeThemeId);
       
       if (selectedTheme?.theme_properties?.palette) {
         return createCustomTheme(mode, selectedTheme.theme_properties.palette);
       }
     }
     // Fallback to default themes
     return mode === "light" ? lightTheme : darkTheme;
   }, [mode, activeThemeId, presetThemes, customThemes]);

3.5 MODE PERSISTENCE
   
   • Mode stored in localStorage with key "themeMode"
   • Read on initial mount: localStorage.getItem("themeMode")
   • Written on toggle: localStorage.setItem("themeMode", newMode)
   • Survives page refresh and browser restart

4.2 CREATE CUSTOM THEME FUNCTION
   
   Purpose: Transform custom palette into complete MUI theme object
   
   Signature:
   createCustomTheme(mode: 'light' | 'dark', customPalette: Object) → Theme
   
   Implementation:
   ────────────────────────────────────────────────────────────────────
   export const createCustomTheme = (mode, customPalette) => {
     const isLight = mode === "light";
     
     return createTheme({
       palette: {
         mode,
         primary: {
           main: customPalette.active,         // Brand color
           dark: customPalette.layout,          // Sidebar
           light: customPalette.notifications,  // Highlights
         },
         secondary: {
           main: customPalette.interactive,     // Accents
         },
         background: {
           creme: customPalette.surface,
           default: isLight ? "#f9f9f9" : "#1a1a1a",
           paper: isLight ? "#ffffff" : "#3c3c3c",
           customPaper: isLight ? "#ada8a828" : "#e9dfdf18",
         },
         text: {
           primary: customPalette.text_primary || 
                    (isLight ? "#000000" : "#ffffff"),
           secondary: customPalette.text_secondary || 
                      (isLight ? "#555555" : "#b0b0b0"),
         },
         custom: {
           cream: customPalette.surface,
           lightGreen: customPalette.notifications,
         },
         // ... task colors, status colors, etc.
       },
       customGradients: { /* ... */ },
       typography: typography,
       components: {
         MuiDrawer: {
           styleOverrides: {
             paper: {
               backgroundColor: customPalette.layout,
               color: "#ffffff",
             },
           },
         },
       },
     });
   };

4.4 THEME CRUD OPERATIONS
   
   CREATE:
   • User clicks "Create Light Theme" or "Create Dark Theme"
   • Dialog opens with default color values
   • User customizes colors via ColorPicker
   • Submit calls createClientTheme(themeData)
   • Success: reloadThemes() and show snackbar
   
   READ:
   • Themes fetched on mount via fetchClientTheme()
   • Separated into presetThemes and customThemes
   • Displayed in grid with ThemeCard components
   
   UPDATE:
   • User clicks Edit icon on custom theme
   • Dialog pre-fills with existing values
   • User modifies colors
   • Submit calls updateClientTheme(id, themeData)
   • Success: reloadThemes() and show snackbar
   
   DELETE:
   • User clicks Delete icon on custom theme
   • Confirmation dialog appears
   • Confirm calls deleteClientTheme(id)
   • Success: reloadThemes() and show snackbar

4.5 THEME SELECTION FLOW
   
   1. User clicks on theme card
   2. handleThemeSelect(themeId, selectedTheme) called
   3. Determine if theme is for light or dark mode (selectedTheme.is_dark)
   4. Update appropriate state:
      - If is_dark === 0: setSelectedLightThemeId(themeId)
      - If is_dark === 1: setSelectedDarkThemeId(themeId)
   5. Call updateUserTheme(themeData) to save to backend
   6. Theme context automatically updates UI

5.4 THEME CONSISTENCY RULES
   
   DO:
   ✓ Always use theme.palette.* for colors
   ✓ Use semantic color names (primary.main, text.primary)
   ✓ Respect mode-specific computed values
   ✓ Use MUI's sx prop for theming
   ✓ Access custom properties via theme.palette.custom.*
   
   DON'T:
   ✗ Hardcode hex colors directly in components
   ✗ Use inline styles for theme-dependent values
   ✗ Override theme colors with !important
   ✗ Assume color values - always reference theme
   ✗ Mix different color systems (RGB, HSL, hex)

5.5 RESPONSIVE THEME USAGE
   
   import { useMediaQuery } from '@mui/material';
   
   const MyComponent = () => {
     const theme = useTheme();
     const isMobile = useMediaQuery(theme.breakpoints.down('md'));
     
     return (
       <Box
         sx={{
           p: isMobile ? 1 : 3,
           bgcolor: theme.palette.background.paper,
         }}
       >
         Content adapts to screen size AND theme
       </Box>
     );
   };

   import React, { useEffect } from 'react';

   const Layout = () => {
     const theme = useTheme();

         >
           {/* Nav items */}
         </Drawer>
         
         {/* Main content */}
         <Box component="main">
           {/* Page content */}
         </Box>
       </Box>

6.3 TASK STATUS CHIP (Using Fixed Semantic Colors)
   
   import { Chip } from '@mui/material';
   import { useTheme } from '@mui/material/styles';
   
   const TaskStatusChip = ({ status }) => {
     const theme = useTheme();
     
     const getStatusColor = () => {
       switch(status) {
         case 'completed':
           return theme.palette.taskStatus.completed;
         case 'in_progress':
           return theme.palette.taskStatus.in_progress;
         case 'pending':
           return theme.palette.taskStatus.pending;
         case 'overdue':
           return theme.palette.taskStatus.overdue;
         default:
           return theme.palette.taskStatus.pending;
       }
     };
     
     return (
       <Chip
         label={status.replace('_', ' ').toUpperCase()}
         sx={{
           bgcolor: getStatusColor(),
           color: '#ffffff',
           fontWeight: 600,
           textTransform: 'uppercase',
         }}
       />
     );
   };

         sx={{
           bgcolor: theme.palette.background.paper,
           border: `1px solid ${theme.palette.divider}`,
         }}
       >
         <Table>
           <TableHead>
             <TableRow
               sx={{
                 bgcolor: theme.palette.background.customPaper,
               }}
             >
               <TableCell sx={{ color: theme.palette.text.primary, fontWeight: 600 }}>
                 Name
               </TableCell>
               <TableCell sx={{ color: theme.palette.text.primary, fontWeight: 600 }}>
                 Status
               </TableCell>
             </TableRow>
           </TableHead>
           <TableBody>
             {data.map((row) => (
               <TableRow
                 key={row.id}
                 sx={{
                   '&:hover': {
                     bgcolor: theme.palette.action.hover,
                   },
                 }}
               >
                 <TableCell sx={{ color: theme.palette.text.primary }}>
                   {row.name}
                 </TableCell>
                 <TableCell sx={{ color: theme.palette.text.secondary }}>
                   {row.status}
                 </TableCell>
               </TableRow>
             ))}
           </TableBody>
         </Table>
       </TableContainer>
     );
   };

2.2 SEMANTIC COLOR NAMING BENEFITS

    ✅ Why Semantic Names?
    - Easier to understand hierarchy (primary > secondary > tertiary)
    - Theme-agnostic (works with any color scheme)
    - Standard naming convention across projects
    - Easier refactoring and maintenance
    - Better for developers joining the project

    📋 Naming Convention Standard:
    
    PRIMARY (1st level)
    - Most important/dominant color
    - Used for: Main navigation, sidebars, primary dark surfaces
    - Visibility: High contrast, attention-grabbing
    
    SECONDARY (2nd level)
    - Main brand/action color
    - Used for: Primary buttons, links, key CTAs
    - Visibility: Brand identity, main interactions
    
    TERTIARY (3rd level)
    - Supporting accent color
    - Used for: Secondary buttons, subtle accents
    - Visibility: Supporting elements
    
    QUATERNARY (4th level)
    - Highlight/hover color
    - Used for: Hover states, highlights, success indicators
    - Visibility: Interactive feedback
    
    SURFACE (Background accent)
    - Light background color
    - Used for: Soft backgrounds, cards, panels
    - Visibility: Subtle differentiation

4.1 ACCESSING THEME COLORS IN COMPONENTS

    Method 1 - Using useTheme Hook:
    ```javascript
    import { useTheme } from '@mui/material/styles';
    
    const MyComponent = () => {
      const theme = useTheme();
      
      return (
        <Box sx={{ backgroundColor: theme.palette.primary.main }}>
          Content
        </Box>
      );
    };
    ```

    Method 2 - Using sx prop with theme callback:
    ```javascript
    <Box sx={(theme) => ({
      backgroundColor: theme.palette.primary.main,
      color: theme.palette.text.primary
    })}>
      Content
    </Box>
    ```

    Method 3 - Direct palette access:
    ```javascript
    <Box sx={{
      backgroundColor: 'primary.main',
      color: 'text.primary'
    }}>
      Content
    </Box>
    ```

4.2 THEME CONSISTENCY RULES

    ✅ DO:
    - Always use theme color keys instead of hardcoded colors
    - Use semantic color names (primary, secondary, text.primary)
    - Follow the established key structure
    - Test colors in all theme variations (green, blue, purple)

    ❌ DON'T:
    - Don't hardcode hex colors directly in components
    - Don't create new color keys without documentation
    - Don't mix color systems (stick to theme palette)

4.3 ADDING NEW COLORS

    To add new colors, update colorPalettes.js:
    
    ```javascript
    export const colorPalettes = {
      green: {
        colors: {
          // Add new color here
          newColor: "#hexvalue",
        }
      },
      // Add to all palette variations
    };
    ```

    Then reference in theme.js palette section.

4.4 COMPONENT-SPECIFIC STYLING PRIORITY

    1. Use theme palette colors first
    2. Use component-specific palette keys (taskStatus, taskType, etc.)
    3. Use custom colors only when necessary
    4. Document any new custom colors
